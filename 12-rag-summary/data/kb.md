## 检索增强生成

检索增强生成（Retrieval-Augmented Generation，RAG）是一种把外部知识库接进大语言模型的方法。
它的核心思路是：模型回答之前先去检索相关文档片段，把这些片段作为上下文塞进提示词。

RAG 缓解了大语言模型的几个根本限制。模型的训练数据存在知识截止日期，
之后发生的事情它一无所知。RAG 通过从外部知识库检索，把最新信息补充进上下文。
RAG 也缓解了幻觉问题 —— 模型在上下文里看到依据时，编造答案的概率会下降。
另外，RAG 让知识可以低成本更新：不需要重新训练模型，只需要重建向量库。

## 文档分块

文档分块是把长文档切分成若干较小片段的过程，以便每个片段能够被独立地向量化并检索。

块大小的选择需要在上下文完整性与检索精度之间取得平衡。块过大会使单个向量混合多个主题，
稀释语义信号，导致检索结果不精确。块过小则会割裂答案，使语言模型缺少足够的上下文来组织连贯的回答。

实际使用中常以 token 数量衡量块大小，常见区间是三百到五百 token，
并保留相当于块大小百分之十到二十的重叠区域。重叠的作用是让落在切分边界上的句子
仍然完整地出现在相邻的某一块中。

## 向量嵌入

向量嵌入模型把一段文本映射成固定长度的浮点向量，使得语义相近的文本在向量空间中彼此靠近。

嵌入模型分为对称和非对称两种。对称模型对查询和文档使用相同的编码方式，
适合摘要、聚类这类没有明确查询方向的场景。非对称模型为查询和文档分别训练不同的编码前缀，
适用于检索场景，因为查询和文档在语义角色上本就不同。

评估嵌入模型常用的指标是召回率：在一批标注过的查询文档对上，
系统能否把正确的文档召回出来。检索环节常用 Mrr 和 Ndcg 衡量排名质量。

## 倒排索引

倒排索引是从关键词到包含该关键词的文档列表的映射，是全文检索的基础数据结构。

它与向量检索的思路正交。倒排索引擅长处理精确匹配，比如查找某个特定的错误码或者函数名。
向量检索擅长处理语义模糊的情况，比如用户用一个完全不同的说法描述同一个概念。

两者结合构成混合检索。混合检索用倒数排名融合把两路结果合并，
因为两路的分数分布完全不同，不可直接比较，只有排名可以比较。

## BM25 打分算法

BM25 是最经典的稀疏检索算法，也是 Elasticsearch 和 Lucene 默认的打分函数。

它的核心是三个部分：逆文档频率衡量词有多稀有，词频衡量词在文档中出现多少次，
长度归一化防止长文档仅仅因为长就占优。

BM25 的词频是饱和的：一个词出现十次比出现一次相关，但绝不可能相关十倍。
参数 k1 控制这个饱和速度，经验值是 1.2。参数 b 控制长度惩罚的强度，经验值是 0.75。

逆文档频率的定义是 ln(1 + (N - df + 0.5) / (df + 0.5))。
出现在所有文档里的词几乎没有区分度，逆文档频率趋近于零；
只出现在一个文档里的词几乎是指针，逆文档频率最大。

## 混合检索

混合检索把稀疏检索和稠密检索结合起来，同时利用关键词匹配的精确性和语义匹配的相关性。

稀疏检索在精确匹配上表现优秀，稠密检索在语义泛化上表现优秀，两者互相补充。
稀疏检索的优势场景是查找特定的错误码、产品型号或者函数名这类罕见字符串。
稠密检索的优势场景是用户用一个完全不同的说法描述同一个概念。

两路的分数分布完全不同：余弦相似度通常在零点五到零点八五之间，
而 BM25 分数是对数加权和，可能达到十几。所以不能直接加权求和，
必须用倒数排名融合这种只看排名的方法。

倒数排名融合的公式是 score(d) 等于各路 1 除以 k 加 rank 之和，
k 的经验值是六十。k 越大越接近于按名次平均，k 越小越强调头部名次。

## 重排与交叉编码器

重排是混合检索之后的精排环节。向量检索使用双编码器，问题和文档分别编码后比对距离，
速度快但精度有限。重排使用交叉编码器，把问题和文档拼在一起送进模型，
能看到两者的交互，因此更准，但每个候选都要跑一次模型，慢得多。

所以标准做法是两阶段：先召回二十到五十条候选，再用重排模型精排成三到五条。

交叉编码器能看到词与词之间的细粒度交互，因此擅长判断「这段话是否真的回答了这个问题」，
而不仅仅是「语义方向接近」。代价是每个候选都要单独推理一遍。

## 上下文压缩

上下文压缩是把召回的片段裁剪到模型上下文预算内的处理过程。
它的必要性在于摘要类任务的输出远短于输入，冗长的上下文反而会稀释关键信息。

压缩有两种做法。抽取式压缩只做挑选和截断，原句逐字保留，可溯源且没有额外失败点。
生成式压缩让模型重新概括，会丢失信息，并且引入一次额外的模型调用。

抽取式压缩通常按相关度顺序累加预算，超出预算的片段按句子边界截断，
并加上省略号标记，让模型知道这是片段而不是完整论述。

压缩之后引用编号必须重新编号，否则模型会引用一个已经被裁掉的片段。

## Milvus 向量数据库

Milvus 是一个开源的向量数据库，支持稠密向量、稀疏向量和标量字段的统一存储与检索。
它把向量索引、倒排索引和元数据过滤都放在服务端，适合生产规模的数据。

服务端混合检索是 Milvus 的核心能力之一。客户端提交两个子检索请求，
一个走稠密向量索引，一个走 BM25 稀疏倒排索引，服务端用倒数排名融合合并结果。
这样一次网络往返就能拿到混合检索的结果。

BM25 稀疏向量在 Milvus 里是服务端函数的输出。写入时 Milvus 自动对文本字段分词、
计算 BM25 权重并生成稀疏向量，客户端不需要也不能直接写这个字段。

稀疏倒排索引的查询条件是一段文本，服务端会把它转换成稀疏向量再去检索。
分词发生在服务端，用的是内置分析器，对英文友好，对中文效果有限。

服务端检索的一致性级别必须用强一致。用有界一致会被 SDK 映射成一个固定的时间戳，
读到的可能是很早的快照，表现为刚灌完库却只能搜到一两条。

## 摘要式 RAG

摘要式 RAG 和问答式 RAG 的目标不同。问答式要输出和输入差不多长的答案，
摘要式要把一堆片段压成一段简短的文字。

因为输出短，所以上下文里的每一块都必须有用。多余的片段会稀释信号、
诱导模型去引用无关内容，并且拉高成本和延迟。

多问法改写是提升召回覆盖率的常用手段。让模型把原问题改写成几个不同角度的问法，
分别检索后再用倒数排名融合合并，可以减少单一表述导致的召回盲区。

## 光合作用

光合作用是植物、藻类和某些细菌把光能转化为化学能的过程。

光合作用分为两个阶段。光反应阶段发生在类囊体膜上，光合色素吸收光子后，
电子被激发到更高能级，随后沿着电子传递链传递，最终用于合成 ATP 和 NADPH。

暗反应阶段也就是卡尔文循环，发生在叶绿体基质中。这个阶段不直接需要光，
而是利用光反应产生的 ATP 和 NADPH 来固定二氧化碳，合成有机物。

## 数据库索引原理

数据库索引是一种加速查询的数据结构，类似于书籍末尾的索引。

最常见的是 B 树索引，它保持数据有序，因此支持范围查询。

在没有索引的情况下，查询需要全表扫描，复杂度是 O(n)。
使用索引后，查找复杂度降为 O(log n)，但每次写入需要维护索引结构，
带来额外的 I/O 开销。这正是数据库存在「写入放大」问题的原因。

## TCP 三次握手

TCP 建立连接需要三次握手。第一次握手，客户端发送 SYN 报文，声明自己的初始序列号。
第二次握手，服务端回复 SYN 加 ACK，声明自己的初始序列号并确认客户端的序列号。
第三次握手，客户端发送 ACK，确认服务端的序列号。

三次握手的原因是确保双方都能确认对方的发送能力和接收能力都正常。
两次握手无法让服务端确认客户端的接收能力。

## 错误码速查

常见的 HTTP 状态码含义如下。404 表示资源不存在。500 表示服务器内部错误。
502 表示网关收到无效响应。503 表示服务暂时不可用。

ECONNREFUSED 表示目标端口没有进程监听，通常是服务没启动或者端口配错了。
ETIMEDOUT 表示连接超时，说明网络不通或者对方主机无响应。
ENOMEM 表示内存分配失败。ENOENT 表示文件或路径不存在。
