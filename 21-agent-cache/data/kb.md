# 缓存优化知识库

本文件是 `21-agent-cache` 的 `search_knowledge` 工具背后的知识库。
Agent 通过这个工具从这里召回片段 —— 用来演示「工具结果缓存」。

## 什么是缓存击穿（Cache Stampede）

缓存击穿指的是：**某个热点 key 过期瞬间，大量并发请求同时打到后端数据库**，
导致后端瞬时压力暴增甚至崩溃。

普通缓存失效（一个请求回源）没什么问题；
但**并发场景**下，1000 个请求可能同时发现缓存没了，
于是 1000 个请求同时去查数据库。

常见解法：

1. **互斥锁（single-flight）** —— 只放一个请求去回源，其它请求等待结果
2. **逻辑过期** —— 缓存值里带上过期时间，过期后先返回旧值，再异步刷新
3. **随机 TTL** —— 每个 key 的过期时间加一个随机偏移，避免大量 key 同时过期

## 什么是缓存雪崩（Cache Avalanche）

缓存雪崩指的是：**大量 key 在同一时刻集中失效**，导致后端瞬时崩溃。

成因通常是 TTL 被设置成了同一个固定值 —— 比如所有 key 都在 10:00:00 过期。

解法就是**随机化 TTL**：`ttl = 基础值 + random(0, 抖动范围)`。

## 缓存穿透（Cache Penetration）

缓存穿透指的是：**查询一个根本不存在的 key**。

因为缓存里永远没有这个值，所以每次请求都会打到数据库。
恶意攻击者可以用随机 key 刷穿缓存。

解法：

1. **缓存空值** —— 给不存在的 key 也缓存一个空标记（TTL 要短）
2. **布隆过滤器** —— 提前判断 key 是否可能存在
3. **参数校验** —— 明显非法的参数直接拒绝

## Redis 的内存淘汰策略

当 Redis 达到 `maxmemory` 时的处理策略：

- `noeviction` —— 不淘汰，写命令直接报错
- `allkeys-lru` —— 淘汰所有 key 里最近最少使用的
- `allkeys-lfu` —— 淘汰所有 key 里访问频率最低的
- `volatile-lru` —— 只在设了过期时间的 key 里淘汰 LRU
- `volatile-ttl` —— 优先淘汰剩余 TTL 最短的 key

对 LLM 响应缓存来说，`allkeys-lru` 通常比 `noeviction` 更合适 ——
缓存满了应该淘汰旧数据，而不是让整个服务写不进去。

## LLM 响应缓存的特殊之处

给 LLM 响应加缓存，和给普通数据加缓存有本质区别：

### 键必须包含所有影响输出的东西

模型输出是以下所有输入的函数：模型名、消息历史、工具定义、
工具选择策略、温度、max tokens、是否开思考模式。

漏掉任何一个，就会在两个本该不同的请求之间返回错答。
而且症状是「答案看起来很合理」，极难排查。

### 精确匹配缓存在 agentic 场景会失灵

带工具调用的 Agent 链路里，模型每次生成的工具调用 ID 都不一样。
这个 ID 进入了消息历史，也就进入了缓存键 —— 于是每次都是未命中。

所以精确匹配缓存真正有效的场景是「单轮问答」，
而不是「多轮工具调用」。

### 语义缓存（semantic cache）走的是另一条路

语义缓存把问题向量化，找最相似的历史问题返回它的答案。
它能跨表述命中，但在 agentic 场景下「走得很偏」——
因为两个表述相似的问题，所需的工具调用序列可能完全不同。
